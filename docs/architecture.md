# Architecture

```
Source file
    │
    ▼
┌──────────────┐   tokens   ┌──────────────┐   AST    ┌──────────────┐
│ Lexer (Flex) │ ─────────► │ Parser       │ ───────► │ AST printer  │
│  lexer.l     │            │ (Bison)      │          │  ast.c       │
└──────────────┘            │  parser.y    │          └──────────────┘
                            │      │       │
                            │      ▼       │
                            │ Symbol table │
                            │ (semantic)   │
                            └──────────────┘
```

## Phases

1. **Lexical analysis (`lexer.l`)**
   Turns the character stream into tokens: `IF`, `ELSE`, `TYPE`, `ID`, `NUMBER`, `FLOATNUM`, `RELOP` and the punctuation `= ; ( ) { }`. Whitespace and `//` comments are skipped. Unknown characters produce an `INVALID` token and a lexical error.

2. **Syntax analysis (`parser.y`)**
   An LALR(1) parser generated by Bison. It checks that every `if` has a parenthesised condition and a braced block. It also checks that `else` only follows an `if` block and that blocks are balanced. On error it reports the line and the expected token.

3. **Semantic analysis (in `parser.y` actions)**
   A simple symbol table (an array of names):
   - `declare_variable()` flags duplicate declarations.
   - `check_variable()` / `check_expression()` flag use of undeclared identifiers in assignments and conditions.

4. **AST construction (`ast.c`)**
   Each node has `type`, `value`, `left`, `right` and `next` (for statement lists). `print_ast()` prints the tree and `free_ast()` releases its memory.

## AST layout for `if`

```
IF
├── left : Condition "a > 10"
└── right: Body
           ├── left : Block (then-part)
           └── right: ELSE / ELSE-IF / NULL
```
